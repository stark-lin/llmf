Convert the supplied customer, stakeholder, or field notes into an engineering
brief.

Distinguish stated facts from interpretations.

Extract:

- the customer's current workflow;
- the problem they are actually experiencing;
- affected users and systems;
- frequency and impact;
- technical and organisational constraints;
- existing workarounds;
- desired outcome;
- unresolved questions;
- the smallest useful next validation step.

Do not convert feature requests directly into requirements without identifying
the underlying problem.

Return Markdown using this structure:

# Current workflow

# Problem

# Impact

# Constraints

# Existing workaround

# Desired outcome

# Open questions

# Next validation step
